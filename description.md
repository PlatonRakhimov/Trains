# Задача: трекер силовых тренировок (Vue 3, офлайн PWA + десктопная рисовалка графиков)

Я хожу в зал по циклической программе. Нужны два независимых веб-приложения:
1. **Мобильное (PWA)**: запись подходов прямо в зале, где НЕТ интернета.
2. **Десктопное**: загрузка экспортированного файла и графики прогресса.

Сервера нет и не будет. Данные живут только на телефоне, на комп переносятся файлом (экспорт → отправляю себе через мессенджер → открываю на компе).

Я новичок во фронтенде, поэтому код должен быть простым и читаемым, с комментариями на русском в неочевидных местах. Сначала предложи структуру проекта и задай уточняющие вопросы, потом пиши код.

## Стек
- Vue 3 (Composition API, `<script setup>`), Vite, обычный JavaScript (без TypeScript).
- Без тяжёлых UI-библиотек, простой собственный CSS. Mobile-first для телефона.
- Графики: Chart.js (через vue-chartjs или напрямую).
- Интерфейс полностью на русском.
- Один репозиторий, два приложения: `mobile/` и `desktop/` (или одна Vite-сборка с двумя точками входа, на твоё усмотрение, но обоснуй выбор). Общий код (формат CSV, парсинг, расчёты) вынести в `shared/`.

## Модель программы (должна редактироваться в приложении)
Программа — это цикл, который повторяется по кругу.
- В цикле **настраиваемое число недель** (сейчас 3).
- В каждой неделе **настраиваемое число тренировок** (сейчас 3). Число тренировок может отличаться от недели к неделе.
- В каждой тренировке список упражнений с планом: число подходов, повторы, необязательный плановый вес, необязательная заметка.
- **Упражнения хранятся в общем справочнике** и ссылаются на него по id. Присед в «Н1Д1» и присед в «Н2Д3» — одно и то же упражнение, и прогресс по нему считается сквозь все тренировки но также должна быть возможность смотреть прогресс только по соответственным тренировкам, Н1Д1 и Н4Д1 (в нашем описанном случае). Переименование упражнения в справочнике не должно ломать историю.
- Редактор программы на телефоне: добавить/удалить/переставить недели, тренировки и упражнения, изменить план. Сделать удобно, но без излишеств. Возможность давать названия неделям и тренировкам (по умолчанию недели - легкая, средняя, тяжелая, тренировки без названий по умолчанию)
- **Изменение программы не должно ломать уже записанную историю.** В логе хранится снимок нужных данных (название тренировки, план на момент записи), а не только ссылка.

## Мобильное приложение: режим «в зале»
Главный сценарий: быстро записать подход и увидеть, что было в прошлый раз.
- Главный экран предлагает **следующую тренировку по порядку** (после Н1Д3 идёт Н2Д1, после последней тренировки цикла — Н1Д1 следующего цикла). Можно выбрать любую другую вручную. Иерархия следующая: сначала выбираем неделю, потом выбираем день на неделе.
- **Номер цикла**: по умолчанию вычисляется автоматически по порядку тренировок (не по датам, пропущенные недели не должны сбивать счёт), но его можно поправить вручную.
- Экран тренировки: список упражнений. У каждого:
  - план (подходы × повторы, вес);
  - **результат этой же тренировки в прошлом цикле**;
  - быстрый ввод подходов: вес (предзаполнен из прошлого раза), повторы, крупные кнопки ±. Добавить подход одним тапом. Отредактировать или удалить подход.
- Пометка к подходу или упражнению: «легко» (+), «тяжело / недобор» (!), короткая текстовая заметка.
- Возможность добавить упражнение не из плана (разовое).
- Тренировка сохраняется сразу при каждом изменении, никаких кнопок «сохранить», которые можно забыть нажать.
- Крупные элементы управления: пользоваться одной рукой между подходами.

## Хранение и офлайн
- Полностью офлайн после первого открытия: Web App Manifest + service worker (vite-plugin-pwa подойдёт). Должно добавляться на главный экран.
- Хранение: IndexedDB (через idb или idb-keyval) или localStorage. Выбери и обоснуй. Объём маленький: примерно 4000 подходов в год.
- При первом запуске вызвать `navigator.storage.persist()`.
- Должно работать и на Android (Chrome)

## Экспорт / импорт (это одновременно и бэкап)
- **Экспорт всегда полный** (весь лог + программа), а не «новое с прошлого раза». Любой последний файл — полная копия.
- Два файла:
  1. `workouts_YYYY-MM-DD.csv`: лог для анализа (формат ниже).
  2. `backup_YYYY-MM-DD.json`: полный бэкап (программа, справочник упражнений, лог, настройки).
- Отправка через `navigator.share({ files })` (системное меню «Поделиться»). Если не поддерживается, fallback на обычное скачивание.
- **Импорт JSON-бэкапа** обратно в телефон (восстановление после потери данных или переезд на новый телефон). Перед заменой спросить подтверждение.
- Показывать «Последний экспорт: N дней назад» и мягко напоминать, если прошло больше 7 дней.

## Формат CSV (общий контракт между приложениями)
Одна строка = один подход. UTF-8 с BOM (чтобы Excel нормально открывал кириллицу), разделитель — запятая, десятичная точка, заголовок в первой строке.

Колонки:
`date, cycle, week, day, workout_name, exercise_id, exercise_name, set_no, weight, reps, planned_reps, planned_weight, flag, rpe, note`

- `date`: YYYY-MM-DD
- `week`, `day`: номер недели в цикле и тренировки в неделе
- `flag`: пусто, `+` или `!`
- `planned_*`: план на момент записи (пусто для упражнений вне плана)

Парсер и генератор CSV вынеси в `shared/` и покрой простыми тестами (Vitest).

## Десктопное приложение: анализ
- Загрузка CSV перетаскиванием файла или кнопкой. Всё работает локально в браузере, без сервера.
- Запоминать последний загруженный файл в localStorage, чтобы не грузить каждый раз (с кнопкой «загрузить новый»).
- Экраны:
  1. **По упражнению** (выбор из списка): графики по датам — рабочий (максимальный) вес, расчётный 1ПМ по формуле Эпли (`weight * (1 + reps / 30)`, брать лучший подход за тренировку), объём (сумма вес × повторы). Таблица истории под графиком.
  2. **По тренировке** (Н1Д1, Н1Д2…): сравнение циклов бок о бок, где каждый цикл — столбец, а упражнения — строки. Компактная запись в ячейке вида `80: 5/5/4`.
  3. **Сводка / проблемы**: упражнения, где плановые повторы не выполнены **два цикла подряд** (застой), и упражнения без роста веса за последние N циклов.
- Можно фильтровать по диапазону дат или циклов.
