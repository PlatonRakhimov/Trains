# Тренировки

Два независимых веб-приложения для силовых тренировок по циклической программе:

- **📱 Дневник в зале** (`mobile/`) — PWA для телефона. Запись подходов без интернета, подсказка «что было в прошлом цикле», редактор программы, экспорт и бэкап.
- **📈 Анализ** (`desktop/`) — для компьютера. Загружаете экспортированный CSV и смотрите графики, сравнение циклов, застои.

Сервера нет. Данные живут только на телефоне и переносятся на компьютер файлом.

## Структура

```
shared/          общий код обоих приложений (без Vue и браузерных API)
  schema.js      структуры данных: программа, упражнения, тренировки
  csv.js         генерация и разбор CSV — контракт между приложениями
  order.js       следующая тренировка, номер цикла, «прошлый раз»
  calc.js        1ПМ, объём, запись «80: 5/5/4», формат чисел
  analysis.js    расчёты для экранов десктопа
  backup.js      JSON-бэкап: сборка и проверка
  sample.js      пример программы для первого запуска
  tests/         тесты (Vitest)
mobile/          приложение для телефона (Vue + vite-plugin-pwa)
  src/store.js   состояние и автосохранение в IndexedDB
  src/screens/   экраны: главный, тренировка, программа, справочник, данные
desktop/         приложение для компьютера (Vue + Chart.js)
site/index.html  стартовая страница со ссылками на оба приложения
.github/workflows/deploy.yml   автодеплой на GitHub Pages
```

Почему две отдельные сборки Vite, а не одна с двумя точками входа: PWA и service worker нужны только телефону, а у приложений разные пути на сайте. Так конфигурации проще и не влияют друг на друга. Общий `package.json` и `node_modules` — один на оба приложения.

## Запуск локально

Нужен Node.js 20 или новее.

```bash
npm install          # один раз
npm run dev:mobile   # телефонное приложение → http://localhost:5173
npm run dev:desktop  # анализ → http://localhost:5174
npm test             # тесты общего кода
```

**Посмотреть мобильное приложение на телефоне во время разработки:** телефон и компьютер в одной Wi-Fi сети, откройте на телефоне `http://<IP-компьютера>:5173` (адрес Vite печатает в строке `Network:`). Так открывается всё, кроме офлайн-режима и установки на главный экран — для них нужен HTTPS, то есть деплой.

## Сборка

```bash
npm run build     # всё в папку dist/
npm run preview   # посмотреть собранное: http://localhost:4173/mobile/ и /desktop/
```

В `dist/` получается готовый статичный сайт:

```
dist/index.html   стартовая страница
dist/mobile/      телефонное приложение (с service worker)
dist/desktop/     анализ
```

## Деплой на GitHub Pages

Один раз:

1. Создайте на GitHub новый репозиторий (например, `trains`; можно приватный, если у вас платный план, иначе публичный — **ваши данные в репозиторий не попадают**, только код).
2. Выложите код:
   ```bash
   git init
   git add .
   git commit -m "Первая версия"
   git branch -M main
   git remote add origin https://github.com/<логин>/trains.git
   git push -u origin main
   ```
3. На GitHub: **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Откройте вкладку **Actions** и дождитесь зелёной галочки у «Deploy to GitHub Pages» (1–2 минуты). Если первый запуск упал из-за того, что Pages ещё не были включены, — нажмите **Re-run jobs**.

Сайт будет по адресу `https://<логин>.github.io/trains/`:

- телефон: `https://<логин>.github.io/trains/mobile/`
- компьютер: `https://<логин>.github.io/trains/desktop/`

Дальше каждый `git push` в `main` сам прогоняет тесты, собирает и публикует новую версию. Если тесты упали — старая версия остаётся на месте.

## Установка на телефон (Android)

1. Откройте в **Chrome** адрес `…/trains/mobile/`.
2. Меню **⋮ → «Добавить на главный экран»** (или «Установить приложение»), подтвердите.
3. Запускайте с иконки. После первого открытия приложение работает **без интернета**.

**Обновления.** После деплоя новая версия скачивается в фоне при следующем запуске с интернетом и включается при следующем открытии. Данные при обновлении не трогаются — они в IndexedDB, а не в кэше приложения.

## Как пользоваться

- **Главный экран** предлагает следующую тренировку по порядку (после Н1Д3 — Н2Д1, после последней — Н1Д1 следующего цикла). Можно выбрать другую: неделя → день. Номер цикла считается по порядку записей, а не по датам, и правится кнопками ±.
- **В тренировке** у каждого упражнения: план, результат этой тренировки в прошлом цикле, ввод веса и повторов крупными кнопками, «+ Подход». Тап по записанному подходу — исправить или удалить. Всё сохраняется сразу.
- Открыли тренировку и ничего не записали — при выходе она удаляется и не сбивает порядок.
- **Программа** (кнопка на главном экране): недели, тренировки, упражнения, план. Изменения не трогают уже записанные тренировки — в журнале хранится снимок плана на момент записи.

## Бэкап и восстановление

**Данные хранятся только на телефоне.** Если удалить приложение, очистить данные Chrome или потерять телефон — без бэкапа они пропадут.

**Экспорт** — экран «Данные» → «Поделиться файлами» → отправьте себе в мессенджер (например, в «Избранное» Telegram). Получаются два файла:

| Файл | Зачем |
|---|---|
| `workouts_ГГГГ-ММ-ДД.csv` | журнал для анализа на компьютере, открывается и в Excel |
| `backup_ГГГГ-ММ-ДД.json` | полный бэкап: программа, справочник, журнал, настройки |

Экспорт всегда **полный**: любой последний файл бэкапа восстанавливает всё. Если с последнего экспорта прошло больше 7 дней, главный экран напомнит.

> Chrome на Android может не разрешить делиться файлом `.json`. Тогда бэкап отправится как `backup_ГГГГ-ММ-ДД.json.txt` — внутри то же самое, восстановление понимает оба варианта.

**Восстановление** (новый телефон, переустановка): установите приложение → «Данные» → «Выбрать файл бэкапа» → выберите последний `backup_…`. Приложение покажет, что в файле, и заменит данные только после подтверждения.

## Анализ на компьютере

Откройте `…/trains/desktop/` (или `npm run dev:desktop`) и перетащите в окно файл `workouts_….csv`. Файл никуда не отправляется — всё считается в браузере. Последний файл запоминается, при следующем открытии загружать его не нужно; новый — кнопкой «Загрузить новый».

- **По упражнению** — графики рабочего веса, расчётного 1ПМ (Эпли: `вес × (1 + повторы / 30)`, лучший подход за тренировку) и объёма; сквозь все тренировки или только одна позиция (например, только Н1Д1).
- **По тренировке** — циклы бок о бок: `80: 5/5/4`, ▼ — план по повторам не выполнен.
- **Сводка / проблемы** — недобор повторов два цикла подряд и упражнения без роста веса за N циклов.
- Фильтр по датам и циклам действует на все экраны.

## Формат CSV

Одна строка — один подход. UTF-8 с BOM, разделитель — запятая, десятичная точка, заголовок в первой строке.

```
date,cycle,week,day,workout_name,exercise_id,exercise_name,set_no,weight,reps,planned_reps,planned_weight,flag,rpe,note,warmup
```

| Колонка | Значение |
|---|---|
| `date` | дата `ГГГГ-ММ-ДД` |
| `cycle`, `week`, `day` | номер цикла, недели в цикле, тренировки в неделе |
| `workout_name` | название тренировки на момент записи |
| `exercise_id`, `exercise_name` | id из справочника (не меняется при переименовании) и название на момент записи |
| `set_no` | номер подхода в упражнении |
| `weight`, `reps` | вес и повторы |
| `planned_reps`, `planned_weight` | план на момент записи; пусто для упражнений вне плана |
| `flag` | пусто, `+` (легко) или `!` (тяжело / недобор) |
| `rpe` | необязательно |
| `note` | заметка (заметка к упражнению — в первом подходе) |
| `warmup` | `1` — разминочный подход, пусто — рабочий. Разминка не учитывается в графиках и проверке плана |

Разбор не зависит от порядка колонок и понимает десятичную запятую — файл можно пересохранить в русском Excel.
